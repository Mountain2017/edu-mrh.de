\begin{merke}[Implizite Typumwandlung]
Bei \code{"Test" + 5} findet eine so genannte implizite \luecke statt: Die Zahl 5, üblicherweise vom Datentyp \code{int}, wird als \luecke[2.5cm] (Datentyp von Text) interpretiert. Das Plus-Zeichen ist dann kein Rechenoperator, sondern eine \luecke[3cm] (Aneinanderhängen) der Zeichen.

Die implizite Typumwandlung ist in Java nur möglich, wenn dabei \luecke[2.5cm] Informationen verloren gehen. Daher gilt in Java folgende Kette:
\begin{center}
\begin{tikzpicture}[x=1cm,y=1cm,node distance=6mm,every node/.style={draw,rounded corners=2pt,minimum height=6mm,minimum width=13mm,font=\ttfamily}]
\node (c) {char}; \node[right=of c] (i) {int}; \node[right=of i] (l) {long}; \node[right=of l] (d) {double}; \node[right=of d] (s) {String};
\draw[-{Stealth}] (c) -- (i); \draw[-{Stealth}] (i) -- (l); \draw[-{Stealth}] (l) -- (d); \draw[-{Stealth}] (d) -- (s);
\end{tikzpicture}
\end{center}
Jeder Datentyp kann direkt in die weiter rechts stehenden umgewandelt werden. Prüfe: \code{double d = 5;} \luecke[1.2cm]\quad \code{int i = 5.0;} \luecke[1.2cm]
\end{merke}

\begin{merke}[Explizite Typumwandlung]
Der gewünschte Zieldatentyp wird in runden Klammern vor den umzuwandelnden Wert geschrieben (englisch: \emph{cast}):\\
\code{int i = (int) 3.7;}\qquad \code{char c = (char) 65;}\qquad \code{int k = (int) 4294967298L;}

\begin{center}
\begin{tabular}{|l|c|c|}\hline
\textbf{Typumwandlung} & \textbf{Startwert} & \textbf{Endwert}\\\hline
double $\rightarrow$ int & 3.0 & \\\hline
double $\rightarrow$ int & 3.7 & \\\hline
double $\rightarrow$ int & $-3.7$ & \\\hline
int $\rightarrow$ char & 65 & \\\hline
int $\rightarrow$ char & 66 & \\\hline
char $\rightarrow$ int & 'a' & \\\hline
long $\rightarrow$ int & 300 & \\\hline
long $\rightarrow$ int & 4294967298 & \\\hline
\end{tabular}
\end{center}
\textbf{Achtung:} Hierbei kann es zu \luecke (nicht alles bleibt erhalten) kommen. Nachkommastellen werden \luecke[2.5cm], nicht gerundet.
\end{merke}
