\begin{merke}[Implizite Typumwandlung]\lueckentext
Bei \code{"Test" + 5} findet eine so genannte implizite \lsg{Typumwandlung} statt: Die Zahl 5, üblicherweise vom Datentyp \code{int}, wird als \lsg[3.5cm]{\code{String}} (Datentyp von Text) interpretiert. Das Plus-Zeichen ist dann kein Rechenoperator, sondern eine \lsg[4cm]{Verkettung} (Aneinanderhängen) der Zeichen.

Die implizite Typumwandlung ist in Java nur möglich, wenn dabei \lsg[3.5cm]{keine} Informationen verloren gehen. Daher gilt in Java folgende Kette:
\begin{center}
\begin{tikzpicture}[x=1cm,y=1cm,node distance=6mm,every node/.style={draw,rounded corners=2pt,minimum height=6mm,minimum width=13mm,font=\ttfamily}]
\node (c) {char}; \node[right=of c] (i) {int}; \node[right=of i] (l) {long}; \node[right=of l] (d) {double}; \node[right=of d] (s) {String};
\draw[-{Stealth}] (c) -- (i); \draw[-{Stealth}] (i) -- (l); \draw[-{Stealth}] (l) -- (d); \draw[-{Stealth}] (d) -- (s);
\end{tikzpicture}
\end{center}
Jeder Datentyp kann direkt in die weiter rechts stehenden umgewandelt werden.\\
Prüfe im Projekt: \code{double d = 5;} \lsg[3cm]{geht (5.0)}\quad \code{int i = 5.0;} \lsg[3cm]{Fehler}\\
{\small\textit{Anmerkung:} Zu \code{String} wandelt Java nur beim Verketten mit \code{+} um (\code{"" + 5}). Eine Zuweisung wie \mbox{\code{String s = 5;}} meldet der Compiler als Fehler.}
\end{merke}

\begin{merke}[Explizite Typumwandlung]
Der gewünschte Zieldatentyp wird in runden Klammern vor den umzuwandelnden Wert geschrieben (englisch: \emph{cast}):\\
\code{int i = (int) 3.7;}\qquad \code{char c = (char) 65;}\qquad \code{int k = (int) 4294967298L;}

\begin{center}
\begin{tabular}{|p{4cm}|c|p{3.5cm}|}\hline
\textbf{Typumwandlung} & \textbf{Startwert} & \textbf{Endwert}\\\hline
\schreibzeile double $\rightarrow$ int & 3.0 & \lsgtext{3}\\\hline
\schreibzeile double $\rightarrow$ int & 3.7 & \lsgtext{3}\\\hline
\schreibzeile double $\rightarrow$ int & $-3.7$ & \lsgtext{$-3$}\\\hline
\schreibzeile int $\rightarrow$ char & 65 & \lsgtext{'A'}\\\hline
\schreibzeile int $\rightarrow$ char & 66 & \lsgtext{'B'}\\\hline
\schreibzeile char $\rightarrow$ int & 'a' & \lsgtext{97}\\\hline
\schreibzeile long $\rightarrow$ int & 300 & \lsgtext{300}\\\hline
\schreibzeile long $\rightarrow$ int & 4294967298 & \lsgtext{2 (Überlauf)}\\\hline
\multicolumn{3}{|l|}{\footnotesize Eigene Beispiele (vorher Endwert vermuten, dann im Projekt prüfen):}\\\hline
\schreibzeile \lsgtext{z.\,B. double $\rightarrow$ int} & \lsgtext{9.99} & \lsgtext{9}\\\hline
\schreibzeile \lsgtext{z.\,B. int $\rightarrow$ char} & \lsgtext{97} & \lsgtext{'a'}\\\hline
\end{tabular}
\end{center}
{\lueckentext\textbf{Achtung:} Hierbei kann es zu \lsg[5cm]{Informationsverlust} (nicht alles bleibt erhalten) kommen. Nachkommastellen werden \lsg[3.5cm]{abgeschnitten}, nicht gerundet.\par}
\end{merke}
