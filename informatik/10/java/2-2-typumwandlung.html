FesthaltenImplizite Typumwandlung

Bei "Test" + 5 macht Java aus der Zahl 5 stillschweigend einen Text. Das heißt implizite Typumwandlung. Java erlaubt sie nur, wenn dabei nichts verloren gehen kann. Deshalb gibt es eine feste Richtung: von char über int und long zu double und schließlich zu String.

Fülle den Merkkasten auf dem Blatt und prüfe die Kette im Projekt: Geht double d = 5;? Geht int i = 5.0;?

⚠️

StolpersteinExplizite Typumwandlung

Entferne die Zeile bei TODO 3. Der Compiler weigert sich, 3.7 in eine int-Variable zu stecken. Warum? Was ginge verloren?
Idee zuerst: Manchmal will man den Verlust in Kauf nehmen, z. B. um aus 3.7 € die vollen Euro zu bekommen. Wie könnte man Java sagen: „Ich weiß, was ich tue“?

Das Konzept

Der Zieldatentyp in runden Klammern vor dem Wert erzwingt die Umwandlung: int x = (int) 3.7;. Das nennt man explizite Typumwandlung (englisch cast). Dabei kann Information verloren gehen: Nachkommastellen werden abgeschnitten, nicht gerundet.

  1. Repariere die letzte Zeile mit einem Cast. Probiere danach (int) -3.7, (char) 66 und (int) 'a'. Trage die Ergebnisse in die Tabelle auf dem Blatt ein.
  2. Was ergibt (int) 4294967298L? Suche dazu nach dem Wertebereich von int.
