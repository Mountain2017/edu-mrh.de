1.6 Endliche Automaten programmieren

Formale Sprachen · Informatik 13 · 2 Stunden

Du kannst: einen deterministischen endlichen Automaten direkt als Java-Code programmieren (Zustand als Attribut, Übergänge als Fallunterscheidung, Fangzustand im else-Zweig) und diese Umsetzung mit der Übergangstabelle aus 1.5 vergleichen.

Code lesenAufgabe 1: Der Bezeichner-Automat

In 1.5 stand der Automat in einer Übergangstabelle, also in Daten: Die Klasse Automat war für jeden Automaten gleich, nur die Tabelle war eine andere. Jetzt steckt der Automat direkt im Programmcode. Beispiel aus dem Compiler: Er muss Namen (Bezeichner) wie zahl2 erkennen, vereinfacht Bezeichner = Buchstabe {Buchstabe | Ziffer}.

Lies den Code, bevor du ihn laufen lässt. Die Zeilennummern sind dieselben wie auf dem Blatt.

📝 Blatt 1.6 · Aufgabe 1

📝

FesthaltenMerkkasten „Einen Automaten als Code programmieren“

Ergänze den Merkkasten auf dem Blatt. Leitfragen: Wo merkt sich das Programm den Zustand? Wonach wird in zustandWechseln zuerst unterschieden, wonach danach? Was wird aus einem Pfeil? Was passiert bei einem Zeichen ohne passenden Pfeil? Warum steht pruefe in der Oberklasse?

Ein Pfeil im Diagramm …

Z1  ──.──▶  Z2

„In Z1 wird . gelesen ⇒ wechsle nach Z2“

… ist eine Zeile im Code

case 1:                       // aus Z1 …
   …
   if (zeichen == '.') {      // … mit .
      zustand = 2;            // … nach Z2
   }

Merkkasten zum Vergleichen

Gegeben: die abstrakte Oberklasse DEA

public abstract class DEA {
   protected int zustand;
   protected final int ZF = 99;                    // Fangzustand

   public abstract void zustandWechseln(char zeichen);
   public abstract boolean istEndzustand();

   public boolean pruefe(String wort) {
      zustand = 0;                                 // ①
      for (int i = 0; i < wort.length(); i++) {    // ③
         zustandWechseln(wort.charAt(i));          // ②
      }
      return istEndzustand();                      // ④
   }
}

In pruefe stecken die vier Regeln aus 1.5: ① Start im Startzustand Z0. ③ Zeichen für Zeichen lesen und dabei ② dem passenden Pfeil folgen. ④ Ist die Restzeichenkette leer, wird akzeptiert, wenn der aktuelle Zustand ein Endzustand ist. Neu gegenüber 1.5: Statt abzubrechen, landet ein Wort ohne passenden Pfeil im Fangzustand ZF und wird dort zu Ende gelesen.

AusblickWie geht es weiter?

🎮 Zustände steuern Programme

Dasselbe Muster aus Zustand und Fallunterscheidung steckt in Spielfiguren (steht, läuft, springt), Ampeln oder Getränkeautomaten. Dort löst ein Ereignis (Taste, Münze) den Zustandswechsel aus, und jeder Wechsel kann zusätzlich etwas tun, z. B. eine Animation starten.

⚙️ Automaten im Compiler

Der Scanner aus dem Nachdenken-Teil ist der erste Schritt jedes Compilers. Danach prüft der Parser mit der Grammatik, ob die Bausteine richtig zusammengesetzt sind. Für verschachtelte Klammern reicht ein endlicher Automat nicht (1.5).
