Rätselprogramm AAufgabe 1: Was berechnet dieses Programm?

Bisher hast du Programme geschrieben. Oft muss man aber fremden Code verstehen: Was macht er, und stimmt er? Auf Maschinenebene gibt es keine sprechenden Namen und keine Einrückung, nur Zellen, Adressen und Sprünge. In Zelle 100 steht die Eingabe.

LOADI 0
STORE 101
LOAD 100
CMPI 0
JEQ 12
MODI 10
ADD 101
STORE 101
LOAD 100
DIVI 10
STORE 100
JMP 2
HOLD
  1. Aufgabe 1a: Speicherplan: Welche Zelle ist Eingabe, welche Ergebnis? Gib ihnen Namen.
  2. Aufgabe 1b: Sprünge: Welcher Sprung führt zurück, welcher nach vorne? Markiere die Schleife.
  3. Aufgabe 1c: Protokolliere auf dem Blatt den Ablauf für (100) = 352: je Durchlauf (100) am Anfang, A nach MODI 10 und (101) danach.
  4. Aufgabe 1d: Schreibe den Algorithmus in Java (Variablen n und s).
  5. Aufgabe 1e: Beschreibe in einem Satz, was das Programm berechnet.
  6. Erst danach: Probiere deine Vermutung im Simulator mit eigenen Zahlen aus.

FesthaltenEin Assemblerprogramm in vier Schritten analysieren

Merkkasten zum Vergleichen

Sprünge deuten üben

Die folgenden Sprünge stammen aus Rätselprogramm C (unten). Was bewirkt jeder?

  • Zelle 18: JMP 2Ein Sprung zu einer kleineren Adresse: Hier schließt sich die Schleife, Zelle 2 ist der Kopf.
  • Zelle 4: JEQ 19Der Sprung führt hinter den Rücksprung in Zelle 18, also aus der Schleife hinaus: Das ist die (umgekehrte) Schleifenbedingung.
  • Zelle 7: JEQ 12Ein bedingter Sprung nach vorn, der innerhalb der Schleife landet: eine Verzweigung im Rumpf.
  • Zelle 11: JMP 14Ein unbedingter Sprung nach vorn am Ende eines Zweigs: Er überspringt den anderen Zweig (Zellen 12 und 13).

FehlersucheAufgabe 3: Das falsche Maximum

Das Programm soll die größere der Zahlen in Zelle 100 und 101 nach Zelle 102 schreiben. Für (100) = 9 und (101) = 4 liefert es aber 4.

LOAD 100
CMP 101
JLT 5
LOAD 100
STORE 102
LOAD 101
STORE 102
HOLD
  1. Aufgabe 3a: Welche Zellen werden für 9 und 4 ausgeführt? Erkläre den Fehler.
  2. Aufgabe 3b: Korrigiere das Programm, indem du einen Befehl einfügst. Achtung: Dadurch verschieben sich die Adressen. Welcher andere Befehl muss sich deshalb ändern? Teste im Simulator.

Selbst bauenAufgabe 4: Teiler zählen (nur im Simulator)

Zum Abschluss der ganze Weg vorwärts: eine Schleife mit einer Verzweigung darin. Übersetze den Java-Code. Speicherplan: n → 100, anzahl → 101, t → 102.

anzahl = 0;
t = 1;
while (t <= n) {
   if (n % t == 0) {
      anzahl = anzahl + 1;
   }
   t = t + 1;
}
Für Schnelle: Erweitere das Programm: In Zelle 103 soll 1 stehen, wenn n eine Primzahl ist (genau zwei Teiler), sonst 0.

NachdenkenBesprecht mündlich

Überlegt zu zweit. Die Hinweise sind zum Nachlesen nach dem Gespräch: Halte dazu den Knopf gedrückt.

Rätsel A verändert die Eingabe in Zelle 100. Warum kann das ein Problem sein, und wie verhindert man es?
So sieht dieselbe Addition wie in 2.2 für einen echten Prozessor (x86, Intel/AMD) aus. Was erkennst du wieder, was ist anders? 
mov eax, [a]     ; LOAD a   (eax ist eines von vielen Registern)
add eax, [b]     ; ADD b
mov [c], eax     ; STORE c
Auch die Assemblersprache ist eine formale Sprache (Kapitel 1). Wie könnte eine EBNF-Regel für eine Programmzeile aussehen?
🚀

AusblickRückblick und wie es weitergeht

🧭 Der ganze Weg

Java-Programm → Compiler → Assembler → Maschinenbefehle im Speicher → Befehlszyklus im Prozessor → Rechenwerk und Busse. Du kennst jetzt jede Stufe, vom Quelltext bis zum Bitmuster auf dem Datenbus.

🔌 Noch tiefer

Wie rechnet das Rechenwerk eigentlich? Es besteht aus Logikgattern (UND, ODER, NICHT), aus denen Addierer und Vergleicher gebaut werden. Das ist die nächste Ebene unter der Registermaschine.
